# 安全策略

本文件定义 AI SDLC Platform 的安全约束。智能体在编写涉及认证、授权、用户输入、数据存储的代码时必须参考此文件。

## 认证

**V1 范围**：
- 暂不实现用户认证和授权
- 所有接口为内部调用，无公开 API
- 延后到 V2 实现基于 token 的认证

**V2 计划**：
- API token 认证
- 基于角色的访问控制（RBAC）
- Worker 身份验证

## 授权

**V1 范围**：
- 无权限控制
- 所有 Worker 可访问所有任务

**V2 计划**：
- Worker 类型与任务类型匹配验证
- Artifact 访问权限控制

## 智能体必须遵守的安全规则

1. **代码执行隔离**：所有代码修改和验证在 Sandbox 中执行，限制文件系统访问范围
2. **命令注入防护**：验收命令通过白名单验证，参数通过数组传递避免字符串拼接
3. **输入大小限制**：需求描述 < 10KB，Patch < 10MB，日志 < 50MB
4. **依赖安全**：使用 `pnpm audit` 定期检查漏洞，锁定依赖版本
5. **密钥管理**：密钥仅通过环境变量传递，禁止硬编码，使用 `.env` 文件（不提交到 Git）
6. **数据库连接**：使用连接池限制并发，密码通过环境变量注入
7. **审计日志**：记录所有工作流创建、任务状态变更、artifact 访问

## 安全审查清单

- [ ] 所有用户输入已通过 Schema 验证
- [ ] 无硬编码密钥或凭证
- [ ] 错误信息不泄露内部实现细节
- [ ] Sandbox 限制已正确配置
- [ ] 新增的依赖已通过 `pnpm audit`
